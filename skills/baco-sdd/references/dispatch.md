# Dispatch details: review reports, cost measure, new conversation

Load this reference when you dispatch a review role, measure cost or open a new conversation. The short rules stay in [SKILL.md](../SKILL.md); this file holds the detail.

## 1. Review roles: report and the check of what they changed

A review role (cold-reader, spec-auditor, simplifier, devils-advocate, task-reviewer, final-reviewer, pr-reviewer, acceptance-validator, ci-triage; `Tools: report` in its header) writes only its own report, at the one path you name in the brief, and returns the verdict, the count of findings per severity and the path; two exceptions: the cold-reader gives no verdict (it returns the count of gaps, the count of questions and the path), and the architect, which also has `Tools: report`, returns a short summary of its proposal and the path (its report holds the proposal; it writes each draft ADR and the architecture README draft itself as files with status `Proposta`, which you review and approve at the gate); whoever acts on the findings (you, or the implementer in a fix round) reads them in that file. Report paths: in a delivery, `docs/entregas/ENT-NNN-<slug>/revisao/` (reviews, numbered `-NN`) or `relatorios/` (CI triage); outside a delivery (phases 2 and 3), `.baco/logs/revisoes/`, git-ignored. Check what a review changed, in every folder the role worked in: before dispatching it, note the output of `git status --porcelain` and of `git status --porcelain --ignored --untracked-files=all -- .baco .worktrees` (ignored paths, which plain `git status` hides); after it, run both again and compare. Any new or changed entry other than the role's own report (and, for the pr-reviewer, its `resposta.md`; for the architect, the new draft files `docs/arquitetura/adr/ADR-NNN-<slug>.md` and the draft `docs/arquitetura/README.md`, which are expected; a scratch copy `.worktrees/copia-*` a reviewer made to run a command is not a finding, and you remove it with `git worktree remove --force <folder>`) is reverted (`git restore <file>`; `git clean -f -- <file>` for an untracked file it created, `git clean -f -X -- <file>` for an ignored one, naming only that file) and becomes a finding against that review. Git cannot see a change inside a file that was already ignored; that is what the read-only tools of the review roles are for; output the test tools write by themselves (for example a test results folder) is reverted the same way and recorded as a pending item to ignore it, not as a finding. Commit a report inside `docs/entregas/` with the delivery records.

## 2. Cost measure

The real usage comes from the transcripts, never from what an agent reports: `baco cost measure` reads the Claude Code and Codex session files of this machine, OpenCode's database and the Antigravity calls recorded by `baco harness-answer`, counts each response once and splits conductor and subagents. Every measurement names your own harness with `--conductor-harness` (`claude-code` or `codex`): without it the engine takes a Claude Code conductor, and a Codex conductor's own session would count as `avulsa`. Measure at the end of a delivery (`baco cost measure ENT-NNN --conductor-harness <harness> --write`, which writes to its `custo.md`, before the acceptance report and again at reconciliation) and at the gate of every stage outside a delivery (phases 0 to 3, a spec evolution): note the time (from `date`) when the stage starts, and at its gate run `baco cost measure --since "<that time>" --label "<stage>" --conductor-harness <harness> --write`, which writes `docs/custo-projeto.md`. `baco cost summary` totals both for the user. A harness the command does not read (not Claude Code, Codex, OpenCode or an Antigravity call recorded by `harness-answer`) is left out of the measure: say so.

## 3. Opening a new conversation

When the reason is a BACO version change (the hook says a newer version of the plugin is installed), never open the new conversation yourself, not even in the Ratoeira: the new one must start from the new version, and only the person starting it guarantees that. Save the `## Retomada` of `progresso.md`, then give the person the suggested title and the request to paste, as below.

In the Ratoeira (detected by `/usr/local/bin/ratoeira-cron` or `~/.config/ratoeira/`), open it yourself with the Ratoeira's own tool for opening a conversation, titled as the current conversation plus a sequence number ("Spec XYZ Desenvolvimento" becomes "Spec XYZ Desenvolvimento 02", then "03"), with the same agent, model and effort as this conversation. The tool keeps them by default; when the plan names the conductor's model and effort, pass them explicitly so the new conversation never falls back to a lighter default. Outside the Ratoeira you cannot open or name a conversation: give the person the suggested title and the request to paste, in a fenced code block. The request is short: the delivery (or spec), the phase, where the state is (for example `docs/entregas/ENT-NNN-<slug>/progresso.md`, section `## Retomada`), the latest trace files (`revisao/trace-spec-<nome>.json`) with their result (proven and pending counts, or "ainda sem rastreio") and this conversation's identifier (the hook's warning names it). The new conversation reads the previous one only when the disk does not answer a doubt, and then by search, never whole (in the Ratoeira, with its tool for reading a conversation; elsewhere, the local conversation file, in Claude Code the transcript under `~/.claude/projects/`, when it may read it).
